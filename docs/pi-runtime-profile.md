# 树莓派运行配置建议

## 目标

在树莓派 5 上保持小车主链路响应流畅，同时支持：

- 持续导航
- 地图与遥测的实时推送
- 浏览器摄像头预览
- 可选的本地语音能力

## 默认运行档位

建议第一次部署时采用如下默认配置：

- 雷达建图：开启
- Nav2 导航：开启
- 本地避障：开启
- Web 遥测流：开启
- 浏览器摄像头预览：开启，但帧率控制在中等水平
- 本地唤醒词：关闭
- 本地 ASR：关闭
- 本地 TTS：关闭

原因：

导航和建图是主任务能力，必须优先保证。语音是可选增强项，在没有实测树莓派延迟之前，不应与控制环路争抢算力。

## 语音能力分级

### 第 0 级：仅浏览器语音

- 麦克风采集在浏览器侧完成
- 后端接收转写文本或音频分片流
- 机器人本地不运行唤醒词

适用场景：

- 需要最快交付
- 尚未确认树莓派温度与 CPU 余量

### 第 1 级：按键说话 + 本地 ASR

- 不启用常驻唤醒词
- 只有在明确开始语音会话时才运行 ASR

适用场景：

- 希望尽量本地化处理语音
- 延迟已验证可接受
- 但仍需严格控制持续 CPU 占用

### 第 2 级：唤醒词 + ASR + TTS

- 本地唤醒词：`贾维斯`
- 唤醒后进入流式 ASR
- 按需语音播报确认或执行结果

适用场景：

- 树莓派剩余算力已经过实测
- 没有明显热降频
- 摄像头与建图帧率仍保持可接受水平

## 推荐模型路线

首选建议：

- 使用 `sherpa-onnx` 作为唤醒词、ASR 与可选 TTS 的统一适配层

原因：

- 同一套推理族更容易打包进 Docker
- 支持离线推理，适合机器人场景
- 官方文档中已经包含面向树莓派的部署说明
- 同时覆盖关键词唤醒与 TTS 能力

## 性能保护原则

建议遵守以下规则：

- 摄像头预览应当先降级，不能让导航先降级
- 语音推理不能阻塞处理安全话题的 ROS2 executor
- 如果 AI 命令解析变重，应放到独立线程或进程池
- WebSocket 负载尽量轻量，优先传元数据和压缩媒体流

## 部署切换矩阵

建议预留如下环境变量开关：

- `JARVIS_ENABLE_WAKE_WORD=false`
- `JARVIS_ENABLE_ASR=false`
- `JARVIS_ENABLE_TTS=false`
- `JARVIS_CAMERA_STREAM_MODE=mjpeg`
- `JARVIS_TELEMETRY_HZ=2`
- `JARVIS_LIDAR_DOWNSAMPLE=1`

这些开关应当足以在不重新构建镜像的前提下，按目标设备性能灵活调参。
